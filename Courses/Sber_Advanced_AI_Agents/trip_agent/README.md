# Trip Agent

## Задача

Агент-помощник по планированию поездок на GigaChat: помогает выбрать
направление (и немного «продаёт» свои варианты), затем ищет рейсы/отели и
бронирует поездку.

## Архитектура

- Один ReAct-агент (`langchain.agents.create_agent`) на GigaChat, доступ через
  локальный прокси `gpt2giga` (OpenAI-совместимый эндпоинт).
- Два навыка (`skills/*/SKILL.md`, версионированные): `destination-advisor` и
  `trip-booking`. Инструменты каждого навыка скрываются из схемы модели, пока
  навык не загружен (`SkillScopedToolsMiddleware`) — это структурный запрет,
  а не просто инструкция в промпте.
- Поиск рейсов/отелей делегируется двум узким дочерним агентам (свой
  инструмент, свой бюджет шагов), родитель получает только текстовый запрос и
  ответ.
- Граница доверия: гейты в мидлварах проверяют состояние перед тем, как
  показать инструмент модели (`BookingReadinessMiddleware` скрывает
  `book_trip`, пока не подтверждены рейс и отель); финальное бронирование
  дополнительно требует явного `y/N` от человека в терминале.
- Надёжное исполнение (`src/queue.py`): `publish → reserve → save → ack`,
  приоритет, ограниченные повторы с уходом в DLQ, отдельные дедуп-таблицы по
  `message_id` (повтор доставки) и `idempotency_key` (повтор бизнес-операции).
- Наблюдаемость: трейсы в Langfuse + метрики `tool_call_count`/`tool_success`
  на каждый вызов инструмента (`ToolMetricsMiddleware`).

## Запуск

1. `cp .env.example .env` и заполнить значения (креды GigaChat для
   `gpt2giga`, ключи Langfuse).
2. `uv sync`
3. Поднять прокси и запустить агента (два терминала или в одном через `&`):
   ```
   uv run gpt2giga
   uv run python main.py
   ```

## Как проверить обязательные сценарии

```
uv run pytest tests/test_scenarios.py
```

Прогоняет все 5 сценариев одной командой (нужен поднятый `gpt2giga`):

1. **Успешный длинный маршрут** — `test_happy_long_route`: выбор
   направления → бронирование → поиск рейсов/отелей → подтверждение → бронь.
2. **Дешёвый маршрут** — `test_cheap_route_skips_tools_entirely`: разговор не
   по теме поездок не вызывает ни одного инструмента.
3. **Отклонённое предложение** — три теста: `book_trip` без подтверждённого
   состояния, `book_trip` при отказе человека (`N`), и структурная проверка,
   что запрещённые на данном этапе инструменты вообще не видны модели.
4. **Временная ошибка** — `test_transient_read_failure_then_success_and_cache`
   (отказ → повтор → успех, результат кэшируется) и
   `test_permanent_read_failure_degrades_gracefully` (исчерпание попыток →
   деградация без падения).
5. **Повторная доставка после сбоя** —
   `test_redelivery_after_crash_does_not_repeat_business_op` (сохранили
   результат, не успели ack — повтор не вызывает провайдера повторно) и
   `test_retry_exhaustion_moves_task_to_dlq` (исчерпание попыток → DLQ).
